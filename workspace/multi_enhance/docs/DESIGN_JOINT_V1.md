# 联合调度 v1 设计（下载 × 增强，带用户旋钮）

**日期：** 2026-10-29  
**地位：** 讨论定稿方向 → 实现前对照本文；人话总览仍见 [`CONCLUSIONS.md`](CONCLUSIONS.md)  
**原则：** 自研联合，**不**仿仓库里既有联合优化器；半途收工只做保险丝，**不**进段前目标。  
**参数表（默认常数）：** [`PARAMS_JOINT_V1.md`](PARAMS_JOINT_V1.md) · [`../priors/joint_v1_params.json`](../priors/joint_v1_params.json)

**算法选型：** 动作空间很小（约十几～二十个 `(下载档,工具)`）→ **枚举打分即该分式下的精确最优**；不在 v1 上 RL/复杂搜索。力气花在分式、约束、旋钮；多段规划等列为失败信号触发后再考虑。

---

## 1. 我们要解决什么

现在的做法是：

1. 先只看下载缓冲 → 定清晰度  
2. 再在该清晰度下，用很保守的余量 → 选增强  

问题：两步各扫门前雪，差网里增强侧过胆小；也接不进「用户想要什么」。

v1 改成：

> **每一段同时选出一对：`(下载档, 增强工具)`**，  
> 选择时看缓冲、网速估计、质量表、耗时表，以及用户旋钮。

半途收工仍然保留，但只在执行层救急，段前按「打算做完」来算。

---

## 2. 明确不做的事

| 不做 | 为什么 |
|---|---|
| 把半途收工写进段前公式 | 不稳定、难量化；当保险丝即可 |
| 照搬仓库旧联合算法当「我们的方法」 | 研究立场；旧实现只可对照 |
| 第一期上 RL | 旋钮与可解释性优先 |
| 第一期改服务端编码梯子 | 范围太大 |
| 用单一 QoE 证明「永远最优」 | 有用户倾向就没有唯一最优 |

---

## 3. 用户旋钮（产品层，先做薄）

两个旋钮，默认都是「均衡」：

### 3.1 胆量（流畅 ↔ 清晰）

| 档 | 用户在说 | 系统含义 |
|---|---|---|
| 保守 | 少卡优先 | 更不愿意选「下载慢 + 增强重」的组合；余量要求更严 |
| 均衡 | 默认 | 中间 |
| 激进 | 画质优先 | 更敢选重组合；仍要求「按表能做完」，不是赌半途收工 |

### 3.2 口味（增强类型）

| 档 | 用户在说 | 系统含义 |
|---|---|---|
| 均衡 | 按表选 | 不额外偏某类工具 |
| 更清晰 | 要更「锐利/高清感」 | 超分类工具加权更高 |
| 更干净/去糊 | 嫌糊、嫌脏 | 同分辨率恢复/去糊类加权更高（现有 restore；以后接去噪） |

旋钮只改**分数里的权重和敢不敢选**，不改工具箱合法性（非法格永远不可选）。

---

## 4. 整条链路里，v1 动哪里

```text
服务端梯子 / MPD          ← 第一期不动
        ↓
下载 + 增强【联合段前选择】← 第一期主改（新 NES）
        ↓
增强执行 + 半途收工       ← 不动逻辑；只统计触发次数
        ↓
播放 / 卡顿测量           ← 评价用
```

| 模块 | v1 |
|---|---|
| 服务端 | 不动 |
| 下载 ABR（旧缓冲映射） | **不再单独先定档**；变成联合候选的一维 |
| 增强挑选（旧 tool_greedy） | **并入联合打分** |
| 工具表 Q/T、合法集 | 继续用；耗时尽量诚实 |
| 半途收工 | 保留；不进打分 |
| 评价 | 卡顿 + 工具分布 + 旋钮是否生效；QoE 附录 |

## 5. 算法：一段里怎么选出一对

动作空间很小：下载档大约 5 个，每档合法工具大约 2～4 个，全部枚举大约十几到二十个组合。  
**v1 就枚举，不搞复杂搜索。**

### 5.1 输入（每段决策时能拿到的）

- 下载缓冲、增强缓冲（秒）  
- 段时长  
- 带宽估计（已有 bandwidth meter；没有就用保守默认）  
- 各下载档码率  
- 质量表 `Q[档, 工具]`、耗时表 `T[档, 工具]`（按「整段做完」）  
- 合法表：该档允许哪些工具  
- 用户旋钮：胆量、口味  

### 5.2 对每个候选 `(档 d, 工具 t)` 算三件事

**① 能不能选（可行性）——按「做完」算，不赌半途收工**

人话：

- 工具必须合法，质量不是「禁止」  
- 预计增强耗时不能离谱超过一段（粗门，防表坏）  
- **下载耗时估计 + 增强耗时** 不能把缓冲吃穿到危险区  

示意（实现时可微调常数，但语义固定）：

```text
预计下载秒 ≈ 该档段数据量 / 带宽估计
预计增强秒 ≈ T[d, t]          # 表内「做完」时间；可再乘一点安全系数

# 胆量影响「危险线」：保守抬高，激进放低
危险线 = 按胆量设定的最小缓冲（例如保守 2 段，均衡 1 段，激进 0.5 段）

粗余量 = 下载缓冲 - 增强缓冲 - 危险线
若 预计下载秒 + 预计增强秒 > 粗余量 + 宽松项 → 淘汰
```

说明：

- 这里**没有**把半途收工算进去。  
- 「胆量」只改危险线和宽松项，不改「做完」假设。  
- 若耗时表仍然偏乐观，应**修表或开很轻的耗时修正**，而不是用半途收工去圆。

**② 好不好看（质量项）**

```text
质量分 = Q[d, t]    # 查表；同一张表口径
```

**③ 合不合口味（类型项）**

```text
若工具是超分类，且口味=更清晰 → 加分
若工具是恢复/去糊类，且口味=更干净 → 加分
若口味=均衡 → 类型项为 0
```

**④ 卡顿风险（可选但建议有）**

即使用过了可行性，仍可对「余量越薄」的组合扣一点分，避免全挤在刀刃上。  
胆量越保守，这项扣得越重。

### 5.3 综合分与选择

```text
总分(d,t) =
    质量分
  + 口味加权
  - 卡顿风险惩罚（受胆量影响）

在所有「能选」的 (d,t) 里取总分最高
若一个都没有 → (最低档, 不增强) 保底
```

这就是联合：  
**不是**先钉死 d 再在行内 argmax；  
**而是** d 和 t 一起比总分。

### 5.4 和旧方法差在哪（对照理解）

| | 现在 tool_greedy | 联合 v1 |
|---|---|---|
| 下载 | 单独由缓冲映射定 | 和工具一起比 |
| 增强 | 该行内余量够再比 Q | 所有合法对一起比 |
| 用户 | 无 | 胆量 + 口味 |
| 半途收工 | 执行层有；决策当不存在 | 同左（明确不进公式） |

## 6. 举例（帮助建立直觉）

假设缓冲一般、带宽一般，口味=更干净，胆量=均衡：

| 候选 | 直观 | 可能结果 |
|---|---|---|
| 高码率 + 不增强 | 下载重，画面靠源 | 带宽紧时可能被可行性刷掉或风险分差 |
| 中码率 + 强超分 | 下载轻点，算力重 | 质量可能高，但增强耗时长 |
| 中高码率 + 去糊 | 下载与增强都中等，合口味 | **更干净模式下容易胜出** |
| 低码率 + 强超分 | 下载很省，增强很重 | 激进+清晰口味可能喜欢；保守模式常刷掉 |

流畅（保守）模式下：更常看到「较低/中档 + 轻工具 / 不增强」。  
清晰（激进）模式下：更常看到「够用的码率 + 更重工具」，但仍要求表上能做完。

## 7. 怎么评价（不为单一 QoE 绑死）

### 7.1 所有模式都报

- 卡顿时长、次数  
- 所选下载档分布、工具分布  
- 半途收工次数（**压力表**，越低越好，但不进训练目标）  
- 查表均分（附录）

### 7.2 旋钮是否生效（第一期验收核心）

| 检查 | 期望 |
|---|---|
| 保守 vs 激进 | 保守：卡顿更少或持平；激进：平均质量/工具更重，卡顿不超过约定上限 |
| 更清晰 vs 更干净 | 工具类型分布明显偏移（超分占比 vs 恢复占比） |
| 相对不增强 | 任意默认旋钮仍应明显好于「完全不增强」（底线） |
| 相对旧 tool_greedy | 差网不应再系统性「更怂还更卡」；至少不显著更差 |

### 7.3 对照臂（实验）

- 不增强  
- 旧：缓冲下载 + tool_greedy  
- 永远最强超分（可选）  
- 联合 v1 × 几种旋钮组合  
- （可选）仓库旧联合实现只作对照，不改它 |

## 8. 实现落点（工程）

| 项 | 建议 |
|---|---|
| 新 NES 名 | 如 `pref_joint`（名称可再定） |
| 配置 | `--user_courage {conservative,balanced,aggressive}` `--user_taste {balanced,sharp,clean}` |
| 表 | 继续 multitask Q/T；合法集 `LEGAL_BY_DOWNLOAD` |
| 带宽 | 用现有 BandwidthMeter；缺失时保守 |
| 日志 | 每段记下：候选数、胜出对、淘汰原因（可行性/分低）、旋钮 |
| 半途收工 | 配置不变；分析时单列 |

**不**在 v1 改 enhancer 主路径；**不**改 BONES 代码来「变出」我们的方法。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 耗时表仍偏乐观 → 激进模式狂卡 | 先修/重测 T；激进也保留危险线；半途收工托底但计次报警 |
| 枚举联合变成「变相总选最重」 | 卡顿风险项 + 保守模式验收 |
| 口味只有锐化占位，主观说不清 | 先验收「分布偏移」；真去糊模型后补主观 |
| 和旧联合基线比不过 | 允许；叙事是自研可解释联合+旋钮，不是刷榜旧目标 |
