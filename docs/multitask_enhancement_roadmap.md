# 方向三：端侧资源感知的多任务视频增强流式传输

## 定位

跳出 BONES 框架的核心方向。BONES 只有**单任务（超分）、单模型（固定4级别）、单目标（VMAF QoE）**，完全不考虑端侧 GPU 资源。本方向扩展为**多任务、多模型、资源感知、多维度指标**的完整系统。

## 与已有工作的关系

| 已有工作 | 关系 |
|---------|------|
| CARES（内容感知资源惩罚） | 本方向的基础——资源感知从"惩罚项"升级为"一等状态变量" |
| VMAF 平滑 | 可复用，振荡惩罚适用于多任务质量指标 |
| 前瞻规划（Lookahead） | 可复用，N段联合优化适用于多任务决策空间 |
| fast_complete | 多任务场景下更复杂，各任务的完成度需要分别追踪 |

## 五个子点与优先级

### 点3：多任务增强调度（最高优先级，核心创新）

- 扩展增强类型：超分(SR)、去模糊(Deblur)、插帧(FI)、去噪(Denoise)、HDR增强
- 决策空间从 `(码率, 增强级别)` 扩展为 `(码率, 增强任务组合, 各任务强度)`
- 资源感知：根据 GPU 利用率/显存/功耗动态选择做哪些增强
- 内容感知：不同内容适合不同增强组合（运动剧烈→去模糊+插帧，静态→超分）

### 点5：自定义评价指标（高优先级，多任务增强的必要配套）

BONES QoE 局限：只看 VMAF，无法衡量插帧/去模糊效果；无资源维度；振荡/卡顿权重不合理。

需设计：
- 多维度质量分：综合 VMAF、帧率、清晰度、噪声
- 资源感知 QoE：纳入能耗、增强延迟
- 效率指标：VMAF/kJ、quality_per_watt、enhancement_throughput
- 统计鲁棒指标：P95 VMAF、质量切换频率、启动延迟

### 点1：扩展超分模型（中优先级，锦上添花）

- 当前只有 IMDN（单帧图像超分，4级别）
- 可引入：轻量视频SR（PSLVRT/LNVRT/MobileVRT）、实时SR（Real-ESRGAN）
- 模型选择本身成为调度决策变量
- 需测量各模型在 RTX 3060Ti 上的延迟-质量曲线

### 点4：研读论文（中优先级，并行推进）

调研方向：
- 视频超分/增强最新进展（CVPR/ICCV/ECCV 2024-2026）
- 自适应视频流（SIGCOMM/NSDI/MMSys 2024-2026）
- 端侧 DNN 推理调度（MobiCom/MobiSys/SOSP）
- 多任务学习/动态计算（CVPR）

### 点2：专门设计视频超分模型（低优先级，长期储备）

- 设计内容自适应、计算可动态调节的视频超分模型
- 风险：周期长、我们优势在系统不在模型
- 策略：先用现成模型验证系统创新，模型层面联合优化作为长期方向

## 分阶段计划

### 阶段0：基础建设（1-2周）

1. 多模型集成：引入1-2个轻量视频超分模型，测量延迟-质量曲线
2. 多任务增强原型：集成去模糊(NAFNet-tiny)和插帧(RIFE-lite)，测量延迟
3. GPU资源监控完善：扩展gpu_monitor.py，实时采集利用率/显存/功耗/温度
4. 文献调研：系统阅读10-15篇论文，明确创新定位

### 阶段1：多任务增强调度框架（2-4周）

1. 扩展决策空间：从(码率, 增强级别)到(码率, 增强任务组合)
2. 资源约束建模：GPU利用率/显存/功耗作为状态变量和约束
3. 调度算法：资源感知的多任务调度算法
4. 仿真器验证：多任务调度 vs 单任务超分

### 阶段2：自定义指标与真实播放器验证（2-4周）

1. 指标设计：多维度质量分和资源感知QoE
2. 真实播放器集成：多任务增强和调度算法集成到iStreamPlayer
3. 真实实验：多轨迹对比 BONES、单任务增强、多任务增强
4. 消融实验：各增强任务独立贡献、资源约束影响

### 阶段3：深化（持续）

1. 模型层面优化（动态计算分配、多任务共享骨干）
2. 理论分析（资源约束下的近最优性）
3. 论文撰写
