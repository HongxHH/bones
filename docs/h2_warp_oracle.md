# H2：时序配准融合 oracle——非学习多帧"借像素"证伪

## 定位

H1 把 QP/MV 当条件通道喂单帧网已证伪（`h1_condnet_falsification.md`）。H2 改让码流时序信息参与**结构性运算**：用相邻帧做时序配准（warping），把当前帧因压缩丢失、但邻帧里存在的细节"搬"过来。在投入训练轻量 VSR 之前，先做一个**不训练**的 oracle，估"非学习时序融合"的质量上限。脚本 `workspace/pacnet/h2_warp_oracle/measure_warp_oracle.py`，结果 `warp_oracle.json`（2026-09-19）。

## 方法

- 数据/口径完全沿用 hard_survey：TOS 源，7 档退化（426/320 宽 × CRF26/34/42 + 426/400k 锚点）× 32 帧，统一 x4 后 bicubic 到 1920×800 对源算逐帧 VMAF(libvmaf) + LPIPS(squeeze)，逐帧配对双侧符号检验。
- 配准：在 LR 灰度上用 **cv2 DIS 稠密光流**（比解码器 16px 块级 MV 更准，是对"免费 MV warping"的**慷慨上界**）算中心帧→邻帧光流，`cv2.remap` 把邻帧 warp 回中心帧。
- 融合（LR 空间，融合后再过同一个 stock l2 = IMDN_RTC + IMDN_medium_DIV2K_x4）：
  - mean / median：对齐帧栈时序均值 / 中值，窗口 ±1（3 帧）、±3（7 帧）；
  - **gated（非学习融合的最佳情况）**：逐像素只在邻帧 warp 后与中心帧 Y 残差 < τ（配准可信的静态/平坦区）时纳入平均，运动/纹理边缘/光流错误处保持中心帧，τ=6/12。
- 基线 single_l2 复现 hard_survey 的 l2（88.92/78.25/56.33/38.36/63.25/44.29/31.62，逐位一致），口径对齐。

## 结果：所有非学习时序融合都不优于单帧

ΔVMAF（多帧 − single_l2，负=更差；全部 p<0.001，LPIPS 同向为负）：

| 退化 | single VMAF | 最佳多帧 gated3 τ6 | 最差 mean7 | gated3 LPIPS Δ |
|---|---|---|---|---|
| anchor 426/400k | 88.92 | **−1.60** | −17.42 | −0.0085 |
| 426 crf26 | 78.25 | **−0.93** | −12.89 | −0.0076 |
| 426 crf34 | 56.33 | **−0.60** | −6.57 | −0.0074 |
| 426 crf42 | 38.36 | **−0.35** | −3.08 | −0.0063 |
| 320 crf26 | 63.25 | **−0.90** | −11.31 | −0.0023 |
| 320 crf34 | 44.29 | **−0.52** | −5.40 | −0.0028 |
| 320 crf42 | 31.62 | **−0.30** | −2.58 | −0.0016 |

单调规律（强证据，非噪声）：

1. **没有任何一档、任何一种融合在 VMAF 或 LPIPS 上赢过单帧 l2**，符号检验一边倒（p≈0）。
2. 窗口越大越差（7 帧 < 3 帧）、均值比中值差（均值对配准误差不鲁棒）；门控越紧（τ 越小）越接近单帧，但 τ→0 的极限就是单帧本身——时序平均**只会缩小劣势、从不越过单帧**。
3. 朴素 mean/median 大幅变差（−1.1～−17.4 VMAF），即便只在高置信静态区平均的 gated 仍稳定为负。

## 原因与判决

低分辨率（270~426p）+ 重 H.264 压缩下：①光流的亚像素误差经 x4 放大成鬼影/模糊，warp 后 Y 残差仍有 2~4（smoke 实测），配准做不到"免费"；②时序聚合抹掉的是 VMAF/LPIPS 真正给分的细纹理与胶片颗粒，而压缩噪声是内容自适应的、不是可被平均掉的纯白噪；③强单帧 l2 已把块状伪影处理掉，再叠时序信息只剩模糊。

**判决：H2 的"非学习时序借像素 / 免费 MV warping"便宜路证伪。** DIS 稠密光流（明显优于解码器块级 MV）都无法在强单帧 l2 上加分，免费的块级 codec MV warp 更不可能。

**未被本探针否定的边界**：完整的**学习型**轻量 VSR（可变形对齐 + 学习融合，BasicVSR-lite/RT-VSR 类）理论上仍可能有增益，但它需要大规模多内容训练数据与预算（违反端侧单视频不大规模重训约束），且 AIM2025 在 270p 主观评测中学习式光流多帧输给轻量 CNN；属高成本、文献已偏悲观的路径，不在端侧主线优先。

## 与前两轮证伪的合流

PAC-Net（加深/多出口=加容量）、H1（codec 元数据当通道=加条件输入）、H2（时序 warp=加邻帧像素）三类**客户端解码后增强**改进，在强单帧 l2 + 低分辨率重压缩上全部不提升 VMAF/LPIPS。三者共同指向同一瓶颈：**画质上限由压缩/下采样后幸存的输入像素决定，而非增强器的容量、条件或邻帧聚合**——与 Orbis(SenSys'25) 消融一致（去掉保像素模块 QoE 跌 168%，去掉增强模型仅跌 34%）。客户端"事后增强"触顶，杠杆在把更多原生像素送到客户端（选择性原生分辨率 tile/ROI 拉取 + 其余区域 SR），而非把均匀压坏的整帧上采样得更巧。
