# 增量传输+渐进增强框架设计

## 1. 核心思想

当前BONES流水线是**严格串行**的：
```
下载整段(4s) → 增强整段(120帧) → 播放整段
```
这导致：
- 首帧延迟大：必须等整段下载+增强完成才能播放
- 资源浪费：低运动帧的增强占用了本可用于高运动帧的GPU时间
- 无法利用下载与增强的并行性

**增量传输+渐进增强**：将视频数据分层，基础层保证可播放，增强层逐步提升质量：
```
下载基础层 → 解码播放(基础质量) → 下载增强层 → 渐进更新显示(增强质量)
                ↘ GPU增强基础层 ↗ （下载与增强并行）
```

## 2. 数据分层设计

### 2.1 帧级分层

每帧分为两层：
- **基础层**：压缩码流的完整帧，可独立解码显示（质量=码率对应的VMAF）
- **增强层**：超分模型的增量数据，与基础层结合后得到增强帧

**增强层数据格式**：
- 方案A（模型输出差分）：存储增强帧与bicubic上采样帧的Y通道差分（压缩后）
- 方案B（模型参数+选择）：存储该帧使用的模型级别和关键参数（极小，需客户端有模型）
- 方案C（特征图增量）：存储模型中间特征图的量化增量（中等大小，质量灵活）

**推荐方案B**（工程最简）：
- 增强层仅存储1字节：增强级别（0=无, 1=low, 2=medium, 3=high）
- 客户端根据级别选择本地模型增强
- 开销可忽略（120帧=120字节/段）
- 与帧级调度天然兼容

### 2.2 段级分层

每段（4s/120帧）分为：
- **基础段**：完整的压缩码流（与当前BONES相同）
- **增强段头**：120字节的增强级别数组 + 4字节段号
- **增强段数据**（可选）：如果采用方案A/C，存储实际增量数据

**传输顺序**：
1. 基础段（必须，优先级最高）
2. 增强段头（小，可与基础段并行传输）
3. 增强段数据（按需，优先级由帧级调度决定）

## 3. 渐进增强解码流程

### 3.1 状态机

每帧有三个状态：
```
[未下载] → [基础层已下载] → [增强层已下载]
                ↓                   ↓
            基础质量播放       增强质量播放
            (可立即显示)       (替换显示)
```

### 3.2 播放循环

```
while playing:
    frame = get_next_frame_from_buffer()

    if frame.enhancement_level > 0 and frame.enhancement_ready:
        # 增强层已就绪，用增强质量
        display(frame.enhanced_version)
    elif frame.enhancement_level > 0 and not frame.enhancement_ready:
        # 增强层未就绪，先显示基础质量，后台增强
        display(frame.base_version)
        async_enhance(frame)  # GPU后台增强，完成后标记ready
    else:
        # 无增强，直接显示基础质量
        display(frame.base_version)

    # 增强完成回调：如果该帧还在缓冲区（未播放），更新为增强版本
    # 如果已播放，丢弃（不影响当前，影响统计）
```

### 3.3 关键优化：提前增强

利用播放缓冲区的"提前量"：
- 当前播放帧为$t$，缓冲区中有帧$t+1$到$t+B$（B=缓冲秒数×30）
- GPU空闲时，提前增强缓冲区中**增强收益最大**的帧
- 增强完成后，该帧在播放时就是增强质量

**调度策略**：
```
when GPU idle:
    candidate_frames = frames in buffer with enhancement_level > 0 and not enhanced
    sort by ΔVMAF_priority = content_benefit × remaining_time_to_play
    enhance the top candidate
```

这自然实现了"高运动帧优先增强"，且不需要帧级调度器的显式干预。

## 4. 与帧级调度的协同

### 4.1 决策流程

```
段级决策（BONES Lyapunov）：
  → 选择码率 r_seg
  → 选择段内最大增强级别 a_max
  → 计算段内增强预算 C_budget

帧级决策（前瞻调度）：
  → 预提取段内120帧的内容特征
  → 在a ∈ {0,...,a_max}和C_budget约束下，最大化总ΔVMAF
  → 输出120帧的增强级别数组

增量传输：
  → 下载基础段（必须）
  → 下载增强段头（120字节，级别数组）
  → 客户端根据级别数组，GPU空闲时提前增强高优先级帧

渐进播放：
  → 播放时如果增强已完成，显示增强质量
  → 如果未完成，显示基础质量，后台继续增强
```

### 4.2 优势叠加

1. **帧级调度**决定"哪些帧值得增强"（内容感知）
2. **增量传输**决定"增强数据何时到达"（不阻塞基础播放）
3. **渐进增强**决定"增强何时生效"（利用缓冲区提前量）

三者结合，实现了从"段级粗粒度"到"帧级细粒度+时间灵活"的全面提升。

## 5. 仿真实现

### 5.1 在现有仿真器中扩展

修改`simulation/simulator.py`：
- 段下载时间：基础段大小/带宽（增强段头可忽略）
- 增强时间：按帧级调度输出的级别数组，逐帧计算GPU时间
- 播放质量：每帧的VMAF取决于播放时增强是否完成
- 关键指标：增强命中率（播放时已增强的帧比例）

### 5.2 增量传输仿真

```
for each segment:
    # 下载基础段
    download_time = base_segment_size / bandwidth
    buffer_level -= download_time
    if buffer_level < 0: stall = -buffer_level, buffer_level = 0

    # 基础段进入缓冲区，可播放
    buffer.add_segment(base_quality, enhancement_levels)

    # GPU提前增强（利用播放前的时间）
    gpu_time_available = buffer_level * 30  # 可增强的帧数
    frames_to_enhance = sorted by priority, take top gpu_time_available
    for frame in frames_to_enhance:
        frame.enhanced = True
        frame.quality = enhanced_vmaf[frame.level]

    # 播放时统计
    for frame in segment:
        if frame.enhanced:
            total_vmaf += frame.enhanced_quality
            enhanced_hit_count += 1
        else:
            total_vmaf += frame.base_quality
```

### 5.3 关键指标

- **平均VMAF**：所有播放帧的VMAF平均（含未增强的基础质量帧）
- **增强命中率**：播放时已增强的帧比例
- **高优先级帧命中率**：内容收益前30%帧的增强命中率
- **GPU利用率**：实际增强时间/可用GPU时间
- **首帧延迟**：从请求到第一帧显示的时间（基础层到达即可）

## 6. 与BONES的对比

| 维度 | BONES | 增量传输+渐进增强 |
|------|-------|------------------|
| 流水线 | 下载→增强→播放（串行） | 下载→播放，增强并行 |
| 首帧延迟 | 整段下载+增强 | 仅基础层下载 |
| 增强粒度 | 段级固定 | 帧级动态 |
| 未增强帧 | 不存在（要么全增强要么全不） | 显示基础质量，可后续增强 |
| GPU利用 | 段内固定开销 | 按需+提前增强，利用率高 |
| 实现复杂度 | 低 | 中（需状态机+异步增强） |

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 增强未完成就播放，质量波动 | QoE下降 | 帧级调度只给高优先级帧分配增强，低优先级帧设为0 |
| GPU增强与播放争用资源 | 卡顿 | 增强在独立线程，优先级低于播放解码 |
| 增量数据格式不兼容 | 无法部署 | 方案B（仅级别数组）完全兼容现有码流 |
| 理论分析复杂 | 论文难写 | 可分解为帧级调度（Lyapunov）+ 增量传输（排队论）两个子问题 |

## 8. 验证计划

1. **仿真验证**：在simulator中实现，对比BONES基线，多轨迹测试
2. **增强命中率分析**：不同带宽/缓冲区下的命中率曲线
3. **消融实验**：帧级调度单独、增量传输单独、两者结合
4. **播放器集成**（可选）：在iStreamPlayer中实现异步增强线程
