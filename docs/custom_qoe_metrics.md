# 自定义评价指标设计

## 一、现有BONES QoE公式分析

### 1.1 公式定义

BONES的QoE公式（来自`simulation/simulator.py`的`report`函数）：

```
QoE = 平均VMAF - 平均振荡 - 平均卡顿 / 10
```

其中：
- **平均VMAF**：所有播放段的VMAF分数的算术平均值
- **平均振荡**：相邻段VMAF绝对差的平均值，即 `mean(|q[i] - q[i-1]|)`
- **平均卡顿**：总卡顿时间 / 段数（单位：秒）

### 1.2 公式的局限性

#### 局限性1：振荡惩罚过重且不加区分

**问题**：
- 振荡的权重与VMAF相同（1单位振荡 = 1单位VMAF），但用户对质量变化的感知并非线性
- 小的质量变化（如VMAF从92变到93）可能完全不被用户感知，但仍然被全额惩罚
- 场景切换时的自然质量变化（如从暗场景到亮场景）和ABR频繁切换导致的抖动，对用户的影响完全不同，但公式不加区分
- 振荡只考虑相邻段的绝对差，没有考虑变化的频率和趋势（持续上升 vs 频繁上下波动）

**影响**：
- 阶段二发现，细粒度码率分配（平方根、4档）虽然VMAF提升更高，但因为档位边界处的码率跳变增加了振荡，整体QoE反而更低
- 这可能不是因为细粒度分配真的更差，而是因为QoE公式对振荡的惩罚过重

#### 局限性2：卡顿惩罚线性且不合理

**问题**：
- `平均卡顿 / 10`，即100ms卡顿 = 1 VMAF，这是一个线性惩罚
- 但实际上，用户对卡顿的感知是非线性的：
  - 短暂卡顿（<100ms）可能完全不被感知
  - 中等卡顿（100ms-1s）会被注意到但可接受
  - 长卡顿（>1s）会严重影响体验，甚至导致用户退出
- 公式没有考虑卡顿事件的数量和分布（一次2s卡顿 vs 四次0.5s卡顿，总时间相同但体验不同）

**影响**：
- 可能高估或低估卡顿对QoE的真实影响
- 无法区分"少量长卡顿"和"频繁短卡顿"的不同体验

#### 局限性3：VMAF均值没有考虑时间分布

**问题**：
- 简单的算术平均值没有考虑VMAF的时间分布
- 例如：
  - 方案A：前半段70分，后半段90分（平均80分）
  - 方案B：全程80分（平均80分）
  - 方案C：频繁在70和90之间切换（平均80分）
- 这三种方案的平均VMAF相同，但主观体验可能差异很大
- 公式没有考虑低质量段的额外惩罚（如VMAF低于80分时，用户体验急剧下降）

**影响**：
- 无法区分"稳定中等质量"和"波动高低质量"的体验差异
- 可能低估了持续低质量段的负面影响

#### 局限性4：没有考虑资源消耗

**问题**：
- QoE只考虑了质量、振荡、卡顿，没有考虑GPU能耗、显存占用、增强延迟等资源消耗
- 在边缘设备（手机、平板）上，资源消耗直接影响设备温度、续航、用户体验
- 两个QoE相同的方案，一个消耗10kJ能量，一个消耗30kJ能量，用户体验显然不同

**影响**：
- 无法评价方案的资源效率
- 可能倾向于选择高资源消耗但QoE略高的方案

#### 局限性5：没有考虑启动延迟和首帧时间

**问题**：
- 公式只考虑了播放过程中的指标，没有考虑启动延迟（从点击播放到首帧显示的时间）
- 启动延迟是用户体验的重要组成部分，尤其是在弱网环境下
- Quick Start机制（BONES的特性）会影响启动延迟，但公式没有体现

**影响**：
- 无法评价启动体验
- 可能倾向于选择启动慢但播放过程质量高的方案

## 二、自定义评价指标设计

### 2.1 设计原则

1. **多维度**：覆盖质量、平滑度、卡顿、资源、启动等多个维度
2. **非线性**：符合用户感知的非线性特性（阈值效应、边际递减）
3. **可解释**：每个维度的权重和公式有明确的物理意义
4. **可比较**：能区分不同方案的差异，有明确的排名
5. **可验证**：能与主观感知实验结果对照

### 2.2 多维度质量分（MD-QoE）

#### 维度1：感知质量分（Perceived Quality）

**改进点**：考虑VMAF的时间分布和低质量惩罚

```
感知质量分 = w1 * 平均VMAF + w2 * 低质量惩罚 + w3 * 质量方差惩罚
```

其中：
- **平均VMAF**：所有段的VMAF平均值（权重w1=0.6）
- **低质量惩罚**：VMAF低于阈值T（如80分）的段，按超出阈值的程度额外惩罚
  - `低质量惩罚 = -mean(max(0, T - VMAF[i])^2) / 100`
  - 平方惩罚意味着严重低质量的影响远大于轻微低质量
- **质量方差惩罚**：VMAF的时间方差，惩罚质量不稳定
  - `质量方差惩罚 = -std(VMAF) * 0.1`

#### 维度2：时序平滑度（Temporal Smoothness）

**改进点**：区分可感知和不可感知的振荡，考虑振荡频率

```
时序平滑度 = - (可感知振荡 + 高频振荡惩罚)
```

其中：
- **可感知振荡**：只计算超过感知阈值（如VMAF差>1.0）的相邻段变化
  - `可感知振荡 = mean(max(0, |q[i] - q[i-1]| - threshold))`
  - 小于阈值的变化不被惩罚（用户感知不到）
- **高频振荡惩罚**：检测频繁上下波动的模式（如q[i-2]<q[i-1]>q[i]<q[i+1]）
  - `高频振荡惩罚 = count(频繁波动模式) * 0.5`
  - 频繁波动比单向变化更令人不适

#### 维度3：卡顿体验（Stalling Experience）

**改进点**：非线性卡顿惩罚，区分卡顿数量和时长

```
卡顿体验 = - (短卡顿惩罚 + 长卡顿惩罚 + 卡顿频率惩罚)
```

其中：
- **短卡顿惩罚**：时长<500ms的卡顿，按线性惩罚（权重较低）
  - `短卡顿惩罚 = sum(min(stall[i], 0.5)) * 0.5`
- **长卡顿惩罚**：时长>500ms的卡顿，按平方惩罚（权重较高）
  - `长卡顿惩罚 = sum(max(0, stall[i] - 0.5)^2) * 2`
  - 长卡顿的影响远大于短卡顿
- **卡顿频率惩罚**：卡顿事件数量的惩罚
  - `卡顿频率惩罚 = count(stall_events) * 0.3`
  - 频繁卡顿比一次长卡顿更令人不适

#### 维度4：资源效率（Resource Efficiency）

**改进点**：考虑GPU能耗、显存占用、增强延迟

```
资源效率 = - (能耗惩罚 + 显存惩罚 + 增强延迟惩罚)
```

其中：
- **能耗惩罚**：GPU总能耗的归一化惩罚
  - `能耗惩罚 = (total_energy / reference_energy) * 2`
  - reference_energy是纯CBR播放的能耗
- **显存惩罚**：峰值显存占用的归一化惩罚
  - `显存惩罚 = (peak_memory / reference_memory) * 1`
- **增强延迟惩罚**：平均增强延迟的惩罚
  - `增强延迟惩罚 = (avg_enhance_latency / 1000) * 0.5`（单位：秒）

#### 维度5：启动体验（Startup Experience）

**改进点**：考虑首帧时间和启动阶段质量

```
启动体验 = - (首帧延迟惩罚 + 启动质量惩罚)
```

其中：
- **首帧延迟惩罚**：从点击播放到首帧显示的时间
  - `首帧延迟惩罚 = max(0, startup_time - 1.0) * 2`（超过1秒后开始惩罚）
- **启动质量惩罚**：前5秒的平均VMAF与整体平均VMAF的差距
  - `启动质量惩罚 = max(0, avg_vmaf - first_5s_vmaf) * 0.5`

### 2.3 综合QoE公式

```
MD-QoE = 感知质量分 + 时序平滑度 + 卡顿体验 + 资源效率 + 启动体验
```

各维度的默认权重：
- 感知质量分：0.4
- 时序平滑度：0.2
- 卡顿体验：0.25
- 资源效率：0.1
- 启动体验：0.05

权重可根据应用场景调整（如直播场景卡顿权重更高，点播场景质量权重更高）。

## 三、与BONES QoE的对比

| 维度 | BONES QoE | MD-QoE |
|------|-----------|--------|
| 质量 | 平均VMAF | 平均VMAF + 低质量惩罚 + 方差惩罚 |
| 振荡 | 所有相邻差的绝对值 | 仅可感知振荡 + 高频振荡惩罚 |
| 卡顿 | 线性惩罚（/10） | 非线性惩罚（短卡顿轻，长卡重重）+ 频率惩罚 |
| 资源 | 无 | 能耗 + 显存 + 增强延迟 |
| 启动 | 无 | 首帧延迟 + 启动质量 |
| 权重 | 固定（1:1:0.1） | 可配置，多维度 |
