# H3：选择性原生分辨率 tile/ROI 拉取 + 其余 SR——等码率 oracle 证伪

## 定位

PAC-Net（加容量）、H1（加码流条件）、H2（加邻帧像素）三路客户端解码后增强全部证伪，共同指向瓶颈在压缩后幸存的输入像素（见 `h2_warp_oracle.md`）。H3 把杠杆移到**输入端**：关键空间区域不做超分、直接从 1080p 源裁切原生高质量 tile（模拟 DASH 高码率 tile 流），其余区域仍走低码率整帧 + l2 超分，拼回 1920×800。投入 tile 编码/播放器集成前，先做等码率离线 oracle 判方向生死。脚本 `workspace/pacnet/roi_tile/measure_roi_oracle.py`，结果 `roi_oracle.json`，帕累托图 `roi_pareto.png`（2026-09-19，TOS，32 帧）。

## 方法

- 画面切 12×5=60 个 160×160 tile（`measure_roi_oracle.py:42-44`）。ROI 面积扫描 0/5/10/20/40%（`:47`），原生 tile 质量 CRF26/30/34（`:46`）。
- 三种选 tile 法：`perframe`（每帧按 Y-MSE 改善排序，上帝上限）、`fixed`（跨帧平均增益的静态掩码）、`center`（到画面中心距离，无参考朴素策略）。
- **真实码率口径**（`:70-99`、`:255`）：低码率整帧 B_low 用 ffprobe 逐 packet 字节/帧数；原生 tile 速率 b_nat[t] 在连续 96 帧、正常 GOP（-g48）上实测（`:186-196`）；ROI 方案 bits/帧 = B_low + Σ(b_nat[t] − B_low/60)，被替换区域按面积均摊返还（ROI 通常更复杂，少返还，对本方向偏保守）。
- **等码率对手前沿**：均匀提分辨率/质量整帧（320/426/640/854 宽 × CRF22-42，bicubic 下采样 + libx264，`gen_ladder.ps1`）+ 全幅 l2，在 (bits/帧, VMAF) 上建前沿，ROI 点按同码率线性插值比 ΔVMAF/ΔLPIPS（`:156`、`:266`）。
- 质量逐帧对 1080p 源算 libvmaf + LPIPS(lpips 包 v0.1 squeeze，离线权重)。

## 原因与判决

单个 160×160 原生 tile（连续帧实测）crf26≈5.8k、crf20≈11.2k bits/帧，而整帧 426crf34 流才 3.2k bits/帧——**一个 tile 覆盖 1/60 面积却花 1.8~3.5 倍整帧预算**；同样码率均匀提到 640crf34（6.8k）能把**整幅**画面经 l2 从 56 拉到 75。VMAF/LPIPS 由全幅清晰度主导，少数锐利孤岛 + 大片模糊严重低效；而均匀提分辨率 + 强单帧 l2 已极高效（640crf30 即 86、854crf26 即 99.75）。

**判决：普通全画幅自适应流媒体场景下，"选择性原生分辨率 tile + 其余 SR" 证伪（NO-GO）。** tile 经济学成立的前提是 ROI 之外的像素根本不显示（360° 视口、用户缩放/ROI 裁切）；全画幅播放时整帧都要看，码率均匀花在分辨率上最优，这正是标准 DASH 阶梯 + 端侧 SR 已经占据的位置。

**未被本探针否定的边界**：①360°/视口/缩放类只显示局部的场景；②主观人脸/显著性加权指标（但 VMAF 差距 5~50 分，主观反转可能性低，未测）；③服务端全画幅"保像素"预处理（Orbis 式，增益来自处处保像素而非空间挑选），属服务端方向，端侧主线不做。

## 方法论教训（失败也记录）

首轮 4 帧冒烟曾得到 +4~15 VMAF 的假阳性，两个口径错误叠加：①采样帧恰好取到片头简单帧（全量 32 帧均匀跨片后基线 84→56，与 hard_survey 一致）；②独立小 tile 编码（32 帧、GOP=32 近似全 I、丢跨 tile 预测）把基线码率抬高约 60 倍，使原生 tile 显便宜。改用连续帧正常 GOP 测速率 + ffprobe 真实整帧码率 + 均匀前沿后结论反转。**任何"省码率"结论必须在真实 GOP/真实整流码率、且与均匀加钱对手等码率比较后才成立。**

## 四路证伪合流

PAC-Net（加容量）、H1（加条件）、H2（加邻帧像素）、H3（输入端选择性送原生像素）在"客户端、单视频、固定通用 SR 网、全画幅标准码率阶梯"设定下全部不成立。客户端无论是解码后增强还是选择性拉取原生 tile，都无法用同样码率打败"均匀码率分配 + 强单帧 SR"。稳定正向的杠杆只剩**编码/码率分配侧**（已验证的 VBR 平方根内容自适应，131 轨迹 100% 胜率）与改变显示形态（视口/360）。
